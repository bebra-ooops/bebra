# Лабораторная работа № 4. Основы работы с системой контроля версий Git и веб-сервисом GitHub.

# Цель работы
Изучить базовые концепции контроля версий, приобрести практические навыки установки и настройки Git, создания локальных и удаленных репозиториев, а также организации структуры для хранения последующих лабораторных работ по программированию.

# Краткие теоретические сведения
Git — это распределенная система контроля версий. Она позволяет фиксировать изменения в файлах (делать «снимки» проекта — коммиты), возвращаться к предыдущим версиям кода и безопасно вести разработку. 

* **Локальный репозиторий** — скрытая папка `.git` на компьютере, где хранится вся история изменений проекта.
* **Удаленный репозиторий** — копия проекта, размещенная на сервере в сети (в данном случае на GitHub). Служит для резервного копирования и демонстрации кода.
* **Коммит (Commit)** — сохранённое состояние проекта с уникальным идентификатором. Каждое сохранение сопровождается осмысленным описанием выполненной работы.

# Ход работы
Для начала я скачала установочный файл Git с официального сайта git-scm.com и запустила установщик, оставив все параметры по умолчанию. После завершения установки я проверила её корректность в терминале, и на экране отобразилась текущая версия программы, что подтвердило успешную установку. Затем я выполнила глобальную настройку Git, указав своё имя и адрес электронной почты.

```
$ git --version
git version 2.56.0.windows.2

$ git config --global user.name "Бортникова Софья"
$ git config --global user.email "sofiomck@gmail.com"
 ```
Далее я создала корневую папку bebra, перешла в неё через терминал и инициализировала Git-репозиторий, после чего внутри папки появилась скрытая директория .git.

```
$ mkdir bebra
$ cd bebra
$ git init
Initialized empty Git repository in C:/Users/Student/bebra/.git/
```
Внутри корневой папки я создала каталог первой лабораторной работы laba1 и рабочий файл main1.py. Проверив состояние репозитория, я увидела, что папка laba1 подсвечена как неотслеживаемая, после чего подготовила файлы к сохранению и сделала первый коммит.

```
$ mkdir laba1
$ git status
On branch master
No commits yet
Untracked files:
  (use "git add <file>..." to include in what will be committed)
        laba1/

$ git add .
$ git commit -m "Initial commit: create structure and laba1"
[master (root-commit) 50c37f1] Initial commit: create structure and laba1
 1 file changed, 1 insertion(+)
 create mode 100644 laba1/main1.py
 ```

Затем я зашла на сайт github.com, вошла в свой аккаунт и через кнопку создания нового репозитория создала публичный репозиторий с именем bebra, оставив пустыми все галочки инициализации (Add a README file, Add .gitignore, Choose a license). После создания репозитория GitHub показал страницу с подсказками, откуда я скопировала и поочередно выполнила три команды для связывания локального репозитория с удалённым. При первом выполнении команды отправки система открыла окно браузера для авторизации на GitHub, и я подтвердила доступ.

```
$ git remote add origin https://github.com/bebra-ooops/bebra.git
$ git branch -M main
$ git push -u origin main

Enumerating objects: 4, done.
Counting objects: 100% (4/4), done.
Writing objects: 100% (4/4), 312 bytes | 312.00 KiB/s, done.
Total 4 (delta 0), reused 0 (delta 0), pack-reused 0 (from 0)
To https://github.com/bebra-ooops/bebra.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.
```

 Обновив страницу репозитория в браузере, я убедилась, что структура папки laba1 появилась в удалённом репозитории. После оформления отчета в формате Markdown я добавила его в папку laba1 и отправила на GitHub.

В ходе выполнения лабораторной работы я установила и настроила систему контроля версий Git, создала локальный репозиторий с правильной структурой каталогов для хранения лабораторных работ, выполнила первый коммит с осмысленным описанием, создала публичный удалённый репозиторий на GitHub, связала локальный репозиторий с удалённым и отправила код командой git push, а также освоила оформление отчётов в формате Markdown.
